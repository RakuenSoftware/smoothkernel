# Linux 7.2.10 / OpenZFS 2.4.4 bring-up

Verified locally on 2026-10-11. This is build evidence, not promotion approval.

## Source and compatibility

- Linux 7.2.10 tarball verified against kernel.org's SHA256 manifest.
- CachyOS 7.2 base patches pinned to `17bb0bb818d283d0dc6e0280a2e9d5b95e66808b`.
- BORE and ACPI patches are upstream verbatim. i915's drifting context was
  refreshed without changing inserted/deleted code and verified with fuzz 0.
- All three Nobara and all three post-Nobara picks still apply. Only the
  USB pollrate documentation hunk retains fuzz 1; no code hunks need fuzz.
- OpenZFS 2.4.4 release tarball SHA256:
  `2a3c70d55a37cc71618a95a60e81ad66530201eb118d37741dc92efcf848c8b1`.
  Its own META declares Linux-Maximum 7.2; it includes the upstream sget_fc()
  conversion. No META override or experimental configure flag is used.

## Checks passed

- Both canonical configs regenerated and archived under `configs/7.2.10/`.
  amd64 used GCC 16.2.1 / binutils 2.47; arm64 used kernel.org's GCC 14.2.0
  nolibc cross toolchain / binutils 2.42. Compiler-derived capability values
  are refreshed again by olddefconfig on native CI builders. The arm64
  cross toolchain lacks the prior userspace-link/RELR capability probes.
- Core configuration invariants: PREEMPT, PREEMPT_DYNAMIC, HZ_1000,
  SCHED_BORE, BBR/FQ, module signing, XFS, CIFS and WireGuard. The amd64
  ROCm/KFD check passes. The existing module-signature enforcement policy
  is unchanged.
- Linux 7.2.10 modules_prepare and compilation of kernel/sched/ (including
  BORE), futex/waitwake, sunrpc/xprtsock, acpi_call, and vc4_kms.o.
- The complete i915.o and amdgpu.o aggregate objects compile against patched
  Linux 7.2.10. These are object builds, not display hardware testing.
- OpenZFS 2.4.4 kernel configure and module build pass against installed
  CachyOS 7.2.7 headers, using their LLVM toolchain settings. zfs.ko and
  spl.ko have vermagic `7.2.7-1-cachyos SMP preempt mod_unload`.
  Objtool warnings remain for spl_panic noreturn annotations and luaD_call
  section analysis; no implicit-declaration or incompatible-pointer errors.
  These warnings still need CI/runtime review. This does not establish exact 7.2.10
  SmoothKernel package compatibility; CI tests that separately.
- Recipe shell syntax, workflow YAML, architecture matrix, resolved example
  environments, and git diff whitespace checks pass.

## Preserved workarounds and added release gate

The serialized deb-utils/deb-dkms packaging, gzip RPM payload override, and
linux-headers virtual Provides fix remain in place. The old 2.4.3 META patch
is retained only as an archived lane for reproducing old releases;
ZFS_PATCHSET is empty in the current examples.

CI now runs `make check-zfs-dkms` after kernel and ZFS package generation on
both native architectures. It extracts the actual zfs-dkms .deb, invokes the
packaged DKMS configure/build hooks against the full matching kernel tree,
and checks both modules' vermagic before artifacts may be uploaded/released.
It uses separate build/source/install trees and does not install/load modules.

## Fresh build and boot tests on .253

Completed 2026-10-11/12 UTC on the Proxmox test host. No production kernel
or pool was changed.

- Fresh unprivileged Debian 13 LXC 9220 (`smoothkernel-72-build`), 16 CPUs,
  24 GiB RAM, GCC 14.2.0 / binutils 2.44. The LXC runs the host kernel;
  it validates package generation and compilation, not boot behavior.
- Commit `4649306` built all three kernel and all twelve OpenZFS packages,
  then passed `make check-zfs-dkms` against the complete matching 7.2.10
  build tree, including both modules' vermagic. Build exit status 0.
- The subsequent VM test found that `zfs-initramfs` did not declare the
  BusyBox requirement enforced by its hook. Commit `33404a2` adds
  `Depends: initramfs-tools, busybox | busybox-static`. Rebuilt the ZFS
  packages through the normal recipe and repeated the packaged-DKMS check;
  both passed. Installing the corrected package automatically pulled
  BusyBox into the minimal VM and initramfs regeneration passed.
- Fresh Debian 13 VM 9221 (`smoothkernel-72-runtime`) installed the actual
  image/header/libc packages and the Debian initramfs ZFS package set.
  `zfs-dracut` is the alternative initramfs package, not installed together
  with `zfs-initramfs`. The package postinst rebuilt and signed zfs/spl
  against the installed headers and installed their compressed modules.
- Booted `7.2.10-smoothkernel`; loaded OpenZFS 2.4.4. Created a RAIDZ1 pool
  on three empty 2 GiB VM disks. Verified 64 random 1 MiB files across
  snapshot rollback, clone, export/import and scrub. Both scrubs repaired
  0 bytes with 0 errors. A 16 MiB SMB upload/download matched byte-for-byte.
- WireGuard handshake and five tunnel pings passed. Separate namespace
  routing/masquerade passed five pings with an nftables NAT counter hit.
- Explicitly enabled `zfs.target`, `zfs-import.target`,
  `zfs-import-cache.service` and `zfs-mount.service` for the test appliance.
  After reboot the pool imported/mounted automatically, all 64 checksums
  still matched, and the SMB payload was unchanged. These upstream
  converted packages initially leave the ZFS startup units disabled.
- Both native CI architecture builds and packaged-DKMS checks passed on
  `33404a2`: [Release run 48](https://github.com/RakuenSoftware/smoothkernel/actions/runs/38175044303).

Observed warnings are retained in the logs: ACPI missing module-description
metadata, Debian alien's rejected LZMA format probe emitting archive-write
warnings (actual extraction/conversion succeeds), and early guest systemd
BPF/AF_VSOCK generator warnings. The minimal cloud image also lacks optional
console-setup. These functional tests do not establish Secure Boot trust or
hardware-specific behavior.

Evidence retained on .253: LXC `/root/smoothkernel-build.log`,
`/root/smoothkernel-zfs-rebuild.log` and their `.exit` status files;
VM `/root/smoothkernel-runtime.log`, `/root/smoothkernel-runtime.exit`,
`/root/pr26.sha256` and `/var/log/apt/term.log`. The pool and test guests
remain available for inspection.
